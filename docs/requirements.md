# 要件定義

## 1. 目的

OSS リポジトリで条件に合う新しい Issue が作成されたとき、LINE に通知し、見逃しを防ぐ。

## 2. 想定利用者・提供形態

- OSS として公開・配布する
- 利用者は本リポジトリを fork(またはテンプレートとして利用)し、自身の GitHub Actions で動かす
- 通知先は利用者本人の LINE 個人トーク

## 3. 機能要件

### 3.1 監視対象の設定

- 監視するリポジトリと、通知対象とするラベルを設定ファイルに記述する
- 設定ファイルはリポジトリ直下の `config.yml`(YAML 形式)とする
- 記入例として `config.example.yml` を用意する
- リポジトリは複数指定できる
- ラベルはリポジトリごとに指定できる
- 次の Issue を通知の対象から除外できる(どちらもデフォルトは除外しない)
  - Pull Request が紐付いている Issue
  - 担当者(assignee)が決まっている Issue
- 除外の設定は全体の既定値として指定し、リポジトリごとに項目単位で上書きできる

### 3.2 新規 Issue の検知

- 監視対象リポジトリの open な Issue のうち、指定ラベルが付いたものを検知する
- 作成後にラベルが付けられた Issue も、ラベルが付いた時点で通知の対象にする
- 同じ Issue を重複して通知しない
- 最後に確認した時点と通知済みの Issue を、状態として GitHub Actions の Repository variables に保存する
- 通知済み Issue の記録は件数の上限を超えたら古い順に削除する(上限は設定で変更できる)。削除済みの Issue は、再び更新されると再通知されることがある
- 初回実行時(状態がないとき)は通知せず、その時点を基準として記録するだけにする

### 3.3 LINE 通知

- LINE Messaging API の push メッセージで利用者本人に送信する
- 1 回の実行で見つかった Issue は 1 通にまとめて送信する(無料枠の節約)
- 該当 Issue がない場合は送信しない
- 1 通の文字数上限(5,000 文字)に収まる件数まで詳細を載せ、残りは「他 N 件」と件数だけ表示する
- 送信に失敗した場合は状態を更新せず、ジョブを失敗扱いにする(次回の実行で再送される)
- 送信前に当月の残りメッセージ通数を確認し、残っていなければ送信しない
  - このとき状態は更新せず、ジョブも失敗扱いにしない
  - 通数が回復した後(翌月)の実行で、溜まった分をまとめて通知する
- 1 件ごとの通知内容
  - リポジトリ名
  - タイトル
  - URL
  - ラベル
  - 作成者
  - 作成日時
  - 本文の冒頭(デフォルト 100 文字。設定で変更できる)
  - 日本語要約(任意機能。3.4 参照)

### 3.4 日本語要約(任意機能)

- OpenAI 互換の Chat Completions API を使い、Issue 内容の日本語要約を生成する
  - 接続先 URL・モデル名・API キーを利用者が指定し、好きな LLM サービス(Gemini、Claude、OpenAI、Ollama など)を使えるようにする
  - 当初は GitHub Models を予定していたが、2026 年 7 月 30 日に提供が終了したため変更した
- 回数制限や料金を節約するため、1 回の実行で見つかった Issue をまとめて 1 リクエストで要約する
- 有効 / 無効を利用者が切り替えられる(デフォルトは無効)
- 無効時、または要約の生成に失敗した場合は、要約なしで通知する

## 4. 非機能要件

### 4.1 実行環境

- GitHub Actions の schedule(cron)で定期実行する
- 実行間隔は利用者が変更できる
- デフォルトの実行間隔は 30 分とする(public / private のどちらのリポジトリでも Actions の無料枠に収まるため)

### 4.2 技術スタック

- TypeScript(Node.js)

### 4.3 コスト

- GitHub Actions と LINE Messaging API の無料枠の範囲で運用できること
- 日本語要約の費用は、利用者が選ぶ LLM サービスによる(要約を無効にすれば費用はかからない)
- 無料枠の目安(2026 年 10 月時点の調査。公式ページでの最終確認が必要)
  - LINE 公式アカウント(コミュニケーションプラン):月 200 通

### 4.4 必要な認証情報

利用者が Actions の Secrets に設定するもの。

| 用途 | 認証情報 |
| --- | --- |
| LINE への送信 | Messaging API のチャネルアクセストークン、送信先のユーザー ID |
| 状態の保存(Repository variables の書き換え) | Fine-grained PAT(権限:Variables の Read and write) |
| Issue の取得 | Actions の `GITHUB_TOKEN` |
| 日本語要約(任意) | 利用する LLM サービスの API キー(ローカル LLM など不要な場合は省略できる) |

## 5. スコープ外(初期リリースでは対応しない)

- 自分へのメンション通知(必要になったら追加を検討)
- Issue へのコメント、クローズ・再オープンなどの状態変化の通知
- グループトークへの通知
- Pull Request の通知

## 6. 未決事項

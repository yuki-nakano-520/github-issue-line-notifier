# 要件定義

## 1. 目的

OSS リポジトリで条件に合う新しい Issue が作成されたとき、LINE に通知し、見逃しを防ぐ。

## 2. 想定利用者・提供形態

- OSS として公開・配布する
- 利用者は本リポジトリを fork(またはテンプレートとして利用)し、自身の GitHub Actions で動かす
- 通知先は利用者本人の LINE 個人トーク

## 3. 機能要件

### 3.1 監視対象の設定

- 監視するリポジトリと、通知対象とするラベルを設定ファイルに記述する
- リポジトリは複数指定できる
- ラベルはリポジトリごとに指定できる

### 3.2 新規 Issue の検知

- 監視対象リポジトリで新規作成された Issue のうち、指定ラベルが付いたものを検知する
- 同じ Issue を重複して通知しない

### 3.3 LINE 通知

- LINE Messaging API の push メッセージで利用者本人に送信する
- 1 回の実行で見つかった Issue は 1 通にまとめて送信する(無料枠の節約)
- 該当 Issue がない場合は送信しない
- 1 件ごとの通知内容
  - リポジトリ名
  - タイトル
  - URL
  - ラベル
  - 作成者
  - 作成日時
  - 本文の冒頭
  - 日本語要約(任意機能。3.4 参照)

### 3.4 日本語要約(任意機能)

- GitHub Models を使い、Issue 内容の日本語要約を生成する
- 有効 / 無効を利用者が切り替えられる
- 無効時、または要約の生成に失敗した場合は、要約なしで通知する

## 4. 非機能要件

### 4.1 実行環境

- GitHub Actions の schedule(cron)で定期実行する
- 実行間隔は利用者が変更できる
- デフォルトの実行間隔は、無料枠の範囲で可能な限り短くする

### 4.2 技術スタック

- TypeScript(Node.js)

### 4.3 コスト

- GitHub Actions、LINE Messaging API、GitHub Models のいずれも無料枠の範囲で運用できること

## 5. スコープ外(初期リリースでは対応しない)

- 自分へのメンション通知(必要になったら追加を検討)
- Issue へのコメント、クローズ・再オープンなどの状態変化の通知
- グループトークへの通知
- Pull Request の通知

## 6. 未決事項

- 重複通知を防ぐための状態(最終確認時刻・通知済み Issue)の保持方法
- 設定ファイルの形式と配置場所
- デフォルトの実行間隔の具体値(Actions の無料枠はリポジトリの public / private で異なる)
- LINE Messaging API の無料メッセージ数の最新値の確認
- GitHub Models の無料枠・レート制限と、超過時の挙動
- 本文冒頭として表示する文字数
